Technique consistant à envoyer des paiements sur le Lightning Network sans intention de les finaliser, dans le but de découvrir des informations sur le réseau, notamment les routes disponibles et les soldes des canaux.

Pour cela, l'expéditeur construit un paiement avec un condensat de paiement (*payment hash*) dont personne ne connaît la préimage. Aucun destinataire ne peut donc le régler. Si le paiement atteint le dernier nœud de la route, celui-ci le rejette avec l'erreur `incorrect_or_unknown_payment_details` (BOLT-04) : l'expéditeur sait alors que la route existe et que chaque canal traversé avait assez de liquidité pour transmettre le montant. Si un nœud intermédiaire ne peut pas transmettre le paiement, il renvoie une erreur comme `temporary_channel_failure`, qui indique le canal en cause. Aucun fonds ne change de mains, puisque le paiement échoue dans tous les cas.

Prenons un exemple. Alice veut payer Bob et hésite entre deux routes. Elle envoie d'abord un paiement de sondage de 100 000 sats sur chacune : le premier revient avec `incorrect_or_unknown_payment_details`, le second avec `temporary_channel_failure`. Elle choisit donc la première route pour son vrai paiement.
