Field in a Bitcoin transaction input that indicates how that input is locked in time. Originally, it was meant to allow the dynamic replacement of transactions in mempools, in order to enable a layer 2 payment system similar to Lightning. However, its use evolved with the introduction of the relative timelock through BIP-0068. The `nSequence` field can now specify a relative delay before a transaction is included in a block. This delay can be defined as a number of blocks, or as a multiple of 512 seconds (that is, real time). Note that this new interpretation of the `nSequence` field is valid only if the `nVersion` field is greater than or equal to `2`. This interpretation of the `nSequence` field is made at the level of Bitcoin's consensus rules. Moreover, at the level of standardness rules, this field is also used to signal RBF. If a transaction includes an `nSequence` lower than `0xfffffffe`, it signals that it is replaceable via RBF (BIP-0125). This signaling is no longer necessary in Bitcoin Core: since version 28.0, full RBF is enabled by default, and the `mempoolfullrbf` option was removed in version 29.0.
