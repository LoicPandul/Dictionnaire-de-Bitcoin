Field of a Bitcoin transaction that indicates the version of the transaction format used. It lets the network distinguish the successive evolutions of the transaction format over time, and apply the corresponding rules. This field has an impact at the level of consensus rules: when `nVersion >= 2`, the interpretation of the `nSequence` field as a relative timelock is enabled, in accordance with BIP-0068. No value assigned to this field, however, invalidates the transaction. On the other hand, the `nVersion` field has standardness rules that currently accept only the values `1`, `2`, and `3`. Version `3` was introduced with Bitcoin Core 28.0 for TRUC (*Topologically Restricted Until Confirmation*) transactions, as defined in BIP-0431. For now, this field is mainly useful for enabling the `nSequence` field and for signaling TRUC transactions.
