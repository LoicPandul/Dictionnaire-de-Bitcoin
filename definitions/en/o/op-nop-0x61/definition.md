Has no effect on the stack or on the state of the script. It makes no move, no check, and no modification. It simply does nothing, and that will not change: `OP_NOP` has never been redefined. Its neighbors `OP_NOP1` (`0xb0`) through `OP_NOP10` (`0xb9`) are distinct opcodes that do nothing by default but that, since Satoshi Nakamoto modified them in 2010, have been used to add new opcodes through soft forks.

Thus, `OP_NOP2` (`0xb1`) and `OP_NOP3` (`0xb2`) have already been used to implement `OP_CHECKLOCKTIMEVERIFY` and `OP_CHECKSEQUENCEVERIFY`, respectively. They are used together with `OP_DROP` to remove the associated time values from the stack, so that script execution can continue whether or not the node has upgraded. `OP_NOP1` through `OP_NOP10` therefore reserve a slot in a script for checking additional conditions, either existing ones or ones that future soft forks may add. In Tapscript, new opcodes instead go through the `OP_SUCCESS` opcodes, which offer a cleaner upgrade path.
