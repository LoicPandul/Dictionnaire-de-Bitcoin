Opcode `0xbd` proposed in BIP-0346 for Tapscript, replacing `OP_SUCCESS189`. It provides a general-purpose transaction introspection mechanism that produces a configurable hash from selected fields of the spending transaction.

The opcode pops from the top of the stack an item called `TxFieldSelector`, a serialized structure that determines which fields of the transaction are included in the hash. This selector can target, as desired: global fields (version, locktime, index of the current input), per-input fields (prevouts, sequences, scriptSigs, values and scriptPubkeys of the spent UTXOs, Taproot annexes), and per-output fields (scriptPubkeys, values). It also offers several modes for selecting inputs and outputs: all of them, only the one at the current index, the first N, or a set of individual indexes. After validating the selector, the opcode pushes onto the stack the 32-byte `SHA256` hash computed from the selected fields.

With an empty `TxFieldSelector`, `OP_TXHASH` produces a hash semantically equivalent to that of `OP_CHECKTEMPLATEVERIFY`, which makes it a strict generalization of BIP-0119. Combined with `OP_CHECKSIGFROMSTACK`, it would make it possible to build arbitrary signature hashes and to emulate `SIGHASH_ANYPREVOUT` as well as other signature modes. This proposal is still a draft for the time being.
