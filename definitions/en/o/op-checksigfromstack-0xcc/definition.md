Opcode `0xcc` proposed in BIP-0348 for Tapscript, replacing `OP_SUCCESS204`. Unlike `OP_CHECKSIG`, which verifies a signature over a hash derived from the current transaction, `OP_CHECKSIGFROMSTACK` verifies a Schnorr signature over an arbitrary message provided directly on the stack.

Execution starts by reading three items from the top of the stack: the public key (top), the message (second position), and the signature (third position). These three items are then removed from the stack. If the public key is empty, the script fails immediately. If it is 32 bytes long, it is interpreted as a BIP-0340 key: a non-empty signature is then verified under the Schnorr scheme against this key and the message, and any invalid signature stops the script. An empty signature pushes an empty vector onto the stack and execution continues normally. A valid signature pushes the value `0x01`. Keys whose length is neither 0 nor 32 bytes are treated as unknown types, and their verification always succeeds, to allow future extensions.

Each verification with a non-empty signature counts toward the sigops budget defined by BIP-0342. This ability to authenticate arbitrary data would open up possibilities such as transaction introspection, delegation of spending rights, and the construction of Lightning Symmetry channels. This proposal is still in Draft status in the BIP repository as of October 2026, so it is not activated on Bitcoin.
