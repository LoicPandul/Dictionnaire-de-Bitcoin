Attack that makes replacing a transaction prohibitively expensive by exploiting node protections against wasted bandwidth, CPU, and memory. The attacker hijacks the rules designed to prevent abuse of the relay system and uses them to block legitimate fee-bumping attempts in a multiparty context.

Two main vectors are exploited. The first abuses rule 3 of BIP-0125, which requires the replacement transaction to pay an absolute fee higher than that of the original transaction and of all its children. The attacker attaches a large child transaction with a low fee rate, which forces the victim to pay disproportionately high fees to carry out a replacement through RBF. The second vector exploits descendant limits: up to Bitcoin Core 30, nodes restrict transactions to 101,000 vbytes of descendants or 25 ancestors/descendants in total. An attacker can saturate these limits with its own child transactions, which completely blocks CPFP. Since Bitcoin Core 31.0 (cluster mempool), these limits are replaced by limits per group of linked transactions (cluster): 64 transactions and 101 kvB by default. Since this version, a replacement must also strictly improve the mempool's fee rate diagram.

![An attacker attaches a 100,000-vB child at 1 sat/vB to the parent transaction, so that any RBF replacement must pay more than the combined fees of the parent and the child, which is more than 102,000 sats.](../../../fr/t/transaction-pinning/assets/image-1.png)

This attack is a serious threat to the Lightning Network and other multiparty protocols, where fee management is essential to meeting settlement time windows. Several countermeasures have been developed: the CPFP carve-out (removed from Bitcoin Core in version 31.0), ephemeral anchors, TRUC transactions (version 3, BIP-0431), and package relay.
