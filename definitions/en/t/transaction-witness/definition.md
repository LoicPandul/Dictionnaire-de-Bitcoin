Component of Bitcoin transactions that was moved by the SegWit soft fork to solve the problem of transaction malleability. The witness contains the signatures and public keys needed to unlock the bitcoin spent in a transaction. In legacy transactions, the witness was the sum of the `scriptSig` of all inputs. In SegWit transactions, the witness is the sum of the `scriptWitness` of each input, and this part of the transaction is now moved into a separate Merkle tree within the block.

Before SegWit, signatures could be slightly modified without being invalidated before a transaction was confirmed, which changed the transaction identifier. This made it difficult to build various protocols, because an unconfirmed transaction could see its identifier change. By separating the witnesses, SegWit makes transactions non-malleable, since any change in the signatures no longer affects the transaction identifier (TXID), only the witness identifier (WTXID). Besides solving the malleability problem, this separation also increases the capacity of each block.
