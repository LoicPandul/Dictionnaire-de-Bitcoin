HTLC on the Lightning Network whose value is too low to justify creating a dedicated output in the commitment transaction, which makes it “trimmed”. In practice, if the HTLC amount is below the channel's dust limit, it would be uneconomical to resolve it on-chain. Instead of creating a separate output, the value of such HTLCs is absorbed into the transaction fees of the commitment transaction.

This mechanism is essential for allowing Lightning channels to relay very small payments, potentially of a single satoshi, without being limited by the dust limit imposed by the Bitcoin protocol. From an operational standpoint, trimmed HTLCs are built and resolved exactly like ordinary HTLCs: they pass normally between nodes and are honored or canceled under the same rules. The difference appears only if the commitment transaction has to be published on-chain, in which case their value is lost to fees instead of being recoverable.

This design does, however, raise security problems. A malicious actor can create many trimmed HTLCs with no intention of resolving them, which forces its counterparty to pay higher transaction fees or destroys part of the channel's value. Several improvements have been proposed, such as redirecting the value of trimmed HTLCs to ephemeral anchors or using probabilistic payments.
