Method of distributing peer addresses across the tables of Bitcoin Core's addrman module. Each address is assigned to a bucket by a hash computation that combines the address itself, the network group it comes from, and a 256-bit secret key (`nKey`) specific to each node. This placement, deterministic but unpredictable from the outside, is meant to prevent an attacker from predicting or controlling which positions they occupy in the tables.

The “new” and “tried” tables use distinct bucketing schemes. In the “new” table, the bucket depends on the source network group and the network group of the address. In the “tried” table, it depends only on the network group of the address itself. This separation of criteria limits an attacker's ability to monopolize buckets from a single source, which is a defense against eclipse attacks.
