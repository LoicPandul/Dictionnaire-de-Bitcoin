Standard script template P2MS, used to set spending conditions on a UTXO. It locks bitcoin using several public keys. To spend that bitcoin, a signature must be provided with a predefined number of the associated private keys. For example, a `2/3` P2MS has `3` public keys with `3` associated secret private keys. To spend the bitcoin locked with this P2MS script, a signature must be made with at least `2` of the `3` private keys. It is a threshold security scheme. This script was standardized in 2011 by Gavin Andresen, with the publication of BIP-0011, just after he took over maintenance of Bitcoin's main client. The opcode `OP_CHECKMULTISIG`, on which it relies, already existed in the original Bitcoin source code, but scripts that used it were not standard before this proposal. Today, P2MS is only marginally used by some applications. The vast majority of modern multisignatures use other script templates such as P2SH, P2WSH, or P2TR. Compared to these, P2MS is extremely basic. The public keys that make it up are revealed as soon as the transaction is received. Using a P2MS is also more expensive than using the other multisig scripts.
