Proposal included in the SegWit soft fork that resolves a malleability vector tied to the dummy element consumed by the `OP_CHECKMULTISIG` and `OP_CHECKMULTISIGVERIFY` operations. Because of a historical off-by-one bug, these 2 opcodes remove one extra element from the stack on top of their basic function. To avoid an error, a dummy value must therefore be included at the start of the `scriptSig` to satisfy the removal and work around the bug. This value is useless, but it must be there for the script to be valid. BIP-0011, which introduced the P2MS standard, advised putting an `OP_0` as the useless value. But this standard was not enforced at the consensus rule level, which means any value could be placed there without invalidating the transaction. This is why `OP_CHECKMULTISIG` and `OP_CHECKMULTISIGVERIFY` contained a malleability vector. BIP-0147 introduces a new consensus rule, called `NULLDUMMY`, requiring this dummy element to be an empty byte array (`OP_0`). Any other value causes script evaluation to fail immediately. This change applies to pre-SegWit scripts as well as P2WSH scripts and required a soft fork.
