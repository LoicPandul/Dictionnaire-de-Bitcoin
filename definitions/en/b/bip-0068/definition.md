Possibility of using relative lock times through the `nSequence` field. This lets a transaction specify a relative delay before it can be included in a block. This delay can be defined as a number of blocks or as a multiple of 512 seconds (that is, real time). Note that this new interpretation of the `nSequence` field is only valid if the `nVersion` field is greater than or equal to `2`. It takes place at the level of Bitcoin's consensus rules. A relative timelock defines a delay counted from the moment an earlier transaction is accepted, whereas an absolute timelock specifies a precise moment before which the transaction cannot be included in a block. BIP-0068 was introduced through a soft fork on July 4, 2016, together with BIP-0112 and BIP-0113, and was activated for the first time using the BIP-0009 method.
