Improvement proposal aimed at developers of Bitcoin wallet software that supports Taproot transactions. Its main goal is to strengthen the privacy of second-layer protocols that may use PTLCs (Point Time Locked Contracts), such as CoinSwap, the Lightning Network, or DLCs (Discreet Log Contracts). To do so, the proposal creates plausible deniability by automatically setting the `nSequence` field of Taproot transactions the way the `nLocktime` field was set in other transaction types to discourage fee sniping attacks. In other words, BIP-0326 asks wallet software to use the `nSequence` field rather than the `nLocktime` field to prevent fee sniping attacks, which provides better privacy for all off-chain protocols that use this field in a similar way. A Taproot transaction with a specific value in the `nSequence` field could then be either an ordinary wallet spend or a settlement transaction of a second-layer protocol with a timelock, making the two cases indistinguishable. If wallet software developers adopt this proposal widely, it would greatly improve the privacy and fungibility of Bitcoin as a whole.
