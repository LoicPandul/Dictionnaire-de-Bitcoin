Introduces a new opcode named `OP_CHECKTEMPLATEVERIFY` (CTV). CTV would make it possible to create non-recursive covenants in transactions, in order to impose specific conditions on how a given coin can be spent, including in future transactions. More precisely, it would make it possible to set conditions on the `scriptPubKey` of a transaction's outputs, based on the `scriptPubKey` of the UTXO spent as input. CheckTemplateVerify is designed to be simple and to have no dynamic state. Its implementation aims to extend Bitcoin's scripting capabilities to facilitate various applications such as transaction congestion control, non-interactive payment channel creation, DLCs, payment pools, and more. This new opcode would be introduced as a replacement for `OP_NOP4`. This change would require a soft fork.
