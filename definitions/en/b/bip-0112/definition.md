Introduces the `OP_CHECKSEQUENCEVERIFY` (CSV) opcode into Bitcoin's Script language. This operation makes it possible to create transactions that become valid only after a certain delay relative to an earlier transaction, defined either as a number of blocks or as a length of time. `OP_CHECKSEQUENCEVERIFY` compares the value at the top of the stack with the value of the input's `nSequence` field. If it is greater than the `nSequence` value, or if any of the other conditions is not met, the script fails; otherwise, execution continues. `OP_CHECKSEQUENCEVERIFY` thus restricts the possible values of the `nSequence` field of the input that spends it, and that `nSequence` field in turn restricts when the transaction containing the input can be included in a block. BIP-0112 was introduced through a soft fork on July 4, 2016, together with BIP-0068 and BIP-0113, and was activated for the first time using the BIP-0009 method.
