Proposal by Brandon Black and Jeremy Rubin that introduces the `OP_INTERNALKEY` opcode in Tapscript. This opcode would replace `OP_SUCCESS203` (`0xcb`) and push the 32-byte x-only representation of the Taproot internal key directly onto the stack during script execution. Without it, a tapscript that needs to reference the internal key must include it explicitly in its data, which consumes 8 additional vB on-chain. `OP_INTERNALKEY` would eliminate this redundancy.

Beyond this space saving, the opcode would open an important use case: re-keying while preserving the Merkle tree. When the internal key of a Taproot output is changed (for example, to add or remove a participant), the scripts in the tree's leaves that hardcode this key become inconsistent. With `OP_INTERNALKEY`, the leaves would be re-keyed automatically, since the opcode would always return the current internal key.
