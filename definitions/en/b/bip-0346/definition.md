Proposal to add the `OP_TXHASH` opcode to Tapscript, which pushes onto the stack the hash of certain selected fields of the current transaction. The choice of fields included in the hash is determined by a parameter of type TxFieldSelector, which specifies precisely which parts of the transaction (inputs, outputs, amounts, sequences, etc.) must be covered. Combined with `OP_CHECKSIGFROMSTACK` (BIP-0348), `OP_TXHASH` would enable a flexible form of transaction introspection and covenants, without requiring a dedicated opcode for each use case. Proposed by Steven Roose and Brandon Black.
