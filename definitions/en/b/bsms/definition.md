Acronym for “Bitcoin Secure Multisig Setup”. BSMS is a protocol standardized by BIP-0129 that makes it possible to create a multisig wallet securely among several signers (hardware wallets, software), guaranteeing that all of them agree on the same configuration before using it.

The protocol works in two rounds of exchanges between a Coordinator and the Signers. In the first round, the Coordinator defines the multisig parameters (M-of-N threshold, script type) and optionally distributes an encryption token (`TOKEN`) to each signer. Each signer then provides their extended public key along with its derivation path and a signature proving that they control the corresponding private key. In the second round, the Coordinator gathers all the keys, generates an output descriptor for the wallet, and sends it back to each signer. Each signer checks that their own key is included and that the first address of the wallet is correct, which serves as a checksum over the whole configuration.

Three encryption modes are possible for the exchanges: no encryption, standard encryption with a shared 64-bit token, or extended encryption with a unique 128-bit token per signer. The encryption uses AES-256-CTR with a key derived through PBKDF2. The BSMS protocol is implemented in Nunchuk, Sparrow, and ColdCard, among others.
