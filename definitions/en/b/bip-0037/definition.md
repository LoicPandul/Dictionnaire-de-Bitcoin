Proposal introduced to let light wallets (Simplified Payment Verification) filter transactions without having to download the full blockchain. This method relies on the concept of Bloom filters, probabilistic data structures used to test membership in a set. These filters let SPV clients receive only the transactions relevant to their wallet, which reduces the bandwidth and memory required for synchronization, notably on mobile phones. Bloom filters are sent to a full node, which responds with Merkle blocks containing only the filtered transactions, the header with the Merkle root, and the branches needed to link these transactions to the root of the Merkle tree. BIP-0037 was criticized for its privacy shortcomings, since it exposes users' addresses and transactions to the full nodes they connect to. To try to remedy this flaw, additional transactions, the “false positives”, can be included to create plausible deniability. However, the volume of false positives needed to reach a satisfactory level of plausible deniability remains considerably high. BIP-0037 was also criticized for the computational load it places on full nodes and for introducing a new DoS attack vector. This option is therefore disabled by default in Bitcoin Core. To enable it, the parameter `peerbloomfilters=1` must be set in the configuration file.
