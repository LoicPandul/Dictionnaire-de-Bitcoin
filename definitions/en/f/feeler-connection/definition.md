Short-lived outbound connection that Bitcoin Core opens every two minutes, once the 10 permanent outbound connections are filled (8 full-relay and 2 block-relay-only). It is limited to the `VERSION`/`VERACK` handshake, to verify that an address corresponds to a reachable Bitcoin node, and then closes.

The feeler connection alternates between two behaviors. If the eviction buffer contains addresses (the case of a collision when inserting into the "tried" table), it tests one: if the existing address responds, the new one is ignored; otherwise, the old one is replaced. This mechanism is called *test-before-evict*. If the buffer is empty, the feeler picks a random address from the "new" table and attempts to connect to it: on success, the address is promoted to "tried".

This mechanism was introduced by Ethan Heilman as a countermeasure to certain types of eclipse attacks. By populating the "tried" table with recently verified addresses, it reduces the proportion of stale addresses and makes it harder to eclipse a node. When no new block has been received for 30 minutes, Bitcoin Core detects a possible stale tip and opens an additional outbound connection to a new peer, to check whether it has a more recent block and to get around a possible network partition. This mechanism is separate from feeler connections.
