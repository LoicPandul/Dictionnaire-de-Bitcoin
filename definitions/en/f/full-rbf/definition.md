Mempool policy that allows any unconfirmed transaction to be replaced by another transaction that spends at least one of the same inputs but pays higher fees, whether or not the original transaction signaled that it can be replaced through the RBF flag (`nSequence` field). In classic RBF (opt-in RBF), only transactions that explicitly enabled this signal can be replaced. Full RBF removes this restriction.

This policy was introduced in Bitcoin Core through the `mempoolfullrbf` configuration option, available starting with version 24.0 (November 2022) with a default value of `0` (disabled). Starting with version 28.0 (October 2024), the option was enabled by default (`mempoolfullrbf=1`), which made Full RBF the standard behavior of Bitcoin Core. The option was then removed in version 29.0: Full RBF became the only behavior, with no way to turn it off.

Full RBF was the subject of intense debate in the community. Its supporters argued that it improves the efficiency of the fee market and strengthens security by removing the false impression that transactions not signaling RBF are irreversible before confirmation. Its opponents pointed out that it complicates use cases that relied on accepting unconfirmed transactions ("zero-conf" transactions), particularly in retail.
