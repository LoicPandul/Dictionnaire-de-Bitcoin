Advanced security mechanism for storing bitcoin, based on a two-step spending process that imposes a delay between the announcement of a withdrawal and its actual execution. In the first transaction, the user signals the intent to move the funds. A waiting period then elapses, during which the legitimate owner can detect any theft attempt and redirect the funds to a secure recovery address ("clawback"). If no intervention takes place, a second transaction finalizes the transfer.

Several technical approaches have been proposed to implement vaults. The first relies on presigned transactions: the spending transactions are signed in advance, then the signing keys are destroyed to guarantee that only the predefined paths remain usable. This method requires no change to the protocol, but it demands rigorous handling of the key destruction. The second approach, more elegant, relies on covenants, that is, constraints applied directly in scripts to limit how a UTXO can be spent. The `OP_VAULT` proposal, formalized in BIP-0345, introduces dedicated opcodes (`OP_VAULT` and `OP_VAULT_RECOVER`) that considerably simplify building vaults at the consensus level, but it was abandoned in favor of `OP_CHECKCONTRACTVERIFY`, which is more general-purpose.

Vaults are particularly well suited to institutional cold storage, where security takes precedence over speed of access to funds.
