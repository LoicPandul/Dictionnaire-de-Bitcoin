Process by which a node downloads and validates the blockchain from the genesis block, and synchronizes with the other nodes of the Bitcoin network. The IBD must be performed when a new full node is launched. At the start of this initial synchronization, the node has no information about previous transactions. It therefore first downloads the block headers, then each block from several nodes of the network, validates it, and adds it to its local copy of the blockchain. To speed up this step, Bitcoin Core by default skips script verification for the blocks located before a recent block considered valid (the `assumevalid` option); the other consensus rules are still verified. Note that the IBD can be long and resource-intensive because of the growing size of the blockchain and of the UTXO set. How fast it completes depends on the computing power of the computer hosting the node, its RAM, the speed of the storage device, and the bandwidth. To give an idea, with a fast internet connection and a node hosted on a recent computer with plenty of RAM, the IBD takes only a few hours. On a single-board computer such as a Raspberry Pi, on the other hand, it can take a week or more.
