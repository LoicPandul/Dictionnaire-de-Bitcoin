Process by which the nodes of the Bitcoin network connect to other nodes to obtain information. When a Bitcoin node is launched for the first time, it has no information about the other nodes on the network. Yet it must establish connections to synchronize on the blockchain with the most accumulated work. Several mechanisms are used to discover these peers, in order of priority:
* The node starts by consulting its local `peers.dat` file, which stores information about the nodes it has previously interacted with. If the node is new, this file will be empty, and the process moves on to the next step;
* With no information in the `peers.dat` file (which is normal for a newly launched node), the node makes DNS queries to the DNS seeds. These servers provide a list of IP addresses of nodes presumed to be active, to establish connections. The addresses of the DNS seeds are hard-coded in the Bitcoin Core code. This step is generally enough to complete peer discovery;
* If the DNS seeds do not respond within 60 seconds, the node can then turn to the seed nodes. These are public Bitcoin nodes listed in a static list of nearly a thousand entries built directly into the Bitcoin Core source code. The new node will use this list to establish a first connection to the network and obtain IP addresses of other nodes;
* In the very unlikely case that all the previous methods fail, the node operator can always manually add IP addresses of nodes to establish a first connection.
