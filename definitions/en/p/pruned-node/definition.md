Full node that prunes the blockchain. Pruning consists of progressively deleting the oldest blocks, after having duly validated them, so as to keep only the most recent ones. The retention limit is set in the `bitcoin.conf` file through the `prune=n` option, where `n` is the maximum size taken up by the blocks in megabytes (MB). If `0` is written after this option, pruning is disabled, and the node keeps the blockchain in its entirety.

Pruned nodes are sometimes considered to be a different type of node from full nodes. Using a pruned node can be particularly attractive for users facing storage capacity constraints. In 2026, a full node needs about 900 GB just to store the blockchain. A pruned node can limit the required storage to as little as 550 MB. Although it uses less disk space, a pruned node maintains a level of verification and validation similar to that of a full node. Pruned nodes therefore give their users stronger trust guarantees than light clients (SPV).
