Fundamental rules in Bitcoin that ensure the integrity of the system by dictating the validation criteria for transactions and blocks. These rules are shared and applied uniformly by all full nodes of the network. A transaction or block that does not follow the consensus rules is systematically rejected, regardless of any other consideration. For example, a transaction with an invalid signature for one of its inputs can never be included in a valid block. A block containing such a transaction would itself be considered invalid by the entire network.

Consensus rules are distinct from the local policy rules applied by each node (relay policy, mempool policy, standardness rules). Local policy rules are configured individually by each node and may vary from one to another, whereas consensus rules are absolute and identical for all. Thus, a transaction valid under the consensus rules can always be included in a block, even if some nodes judge it non-standard. Conversely, a transaction invalid by consensus can never be confirmed, whatever the context.

Consensus rules also form the basis on which soft forks rest: a soft fork consists of restricting the consensus rules by making invalid transactions or blocks that were previously valid. To ease the deployment of a soft fork, standardness rules are often used beforehand to make non-standard the types of transactions that will later be made invalid by consensus, which prevents a non-upgraded miner from including these transactions in a block.
