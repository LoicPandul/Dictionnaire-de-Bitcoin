Quantum attack carried out during the short window when a transaction that has just revealed a public key is waiting for confirmation. The attacker recovers the private key with a CRQC, then signs, in place of the sender, a competing transaction that sends the same funds to an address the attacker controls. It is also called front-running or transaction hijacking.

The starting point is the spend itself. To spend an output whose public key is not already visible, the sender publishes a signature and the matching public key in the transaction's witness (in the scriptSig for a P2PKH). Let's take an example. Alice spends a P2WPKH output whose public key had never been seen: she broadcasts her transaction, which propagates across mempools. An attacker equipped with a CRQC reads the public key in this transaction, recovers the private key with Shor's algorithm, then signs a competing transaction that spends the same output. If the attacker manages to get it confirmed before Alice's, through a replacement transaction that pays higher fees or by mining it directly without broadcasting it, the attacker's transaction wins and Alice is robbed. Chaincode Labs adds that the attacker could also attempt a chain reorganization, or incite other actors to attempt one. When the key is revealed only on this occasion, the window lasts as long as the transaction is unconfirmed, or has only just been mined in a recent block.

This window is measured in minutes, sometimes hours, which sets this attack apart from the long exposure attack. The attacker no longer has unlimited time to break a key: the key must be broken before the transaction confirms, or shortly after. BIP-0360 concludes that short exposure attacks require faster quantum computers and are considered less risky in the short term. Jameson Lopp lists among the worst-case scenarios one where breaking a key would take less than 10 minutes, which would add these attacks to the others.

Unlike long exposure, no best practice avoids it: BIP-0360 states that wallet hygiene cannot prevent it, because revealing the public key is necessary to spend. Almost all current script types are exposed to it, and P2MR, the output type proposed by BIP-0360, does not address it either. According to BIP-0360, complete protection might require post-quantum signatures, which no longer rely on the discrete logarithm, so that the revealed key no longer lets anyone sign in place of the owner. BIP-0361 notes that no quantum proposal surveyed in March 2026 protects against them.

Another approach does not require replacing the signature of the spend itself. Martin Habovštiak described on the bitcoin-dev mailing list, according to Optech Newsletter #348 of April 4, 2025, a multi-step protocol, practically identical to a proposal by Tim Ruffing, known as the Guy Fawkes signature scheme. Alice first commits to her spend without revealing it, using a transaction protected by a post-quantum signature, then waits for that commitment to be deeply confirmed. Only then does she reveal the SHA256 preimage and the spend, and nodes execute the spend only if the first transaction that committed to this preimage also committed to the spend. Optech estimates that this protocol could be deployed by soft fork, but it assumes that the output contains a commitment to a preimage that is never revealed.

*Chaincode Labs uses "short-range attack" for the same attack, a name that BIP-0360 replaced with "short exposure" on January 20, 2025.*
