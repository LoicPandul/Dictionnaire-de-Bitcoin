Digital signature operations required to validate transactions. Each Bitcoin transaction can contain several inputs, and each input may require one or more signatures to be considered valid. These signatures are verified using specific opcodes called "sigops". In practice, this includes `OP_CHECKSIG`, `OP_CHECKSIGVERIFY`, `OP_CHECKMULTISIG`, and `OP_CHECKMULTISIGVERIFY`. These operations put a certain workload on the network nodes that must verify them. To prevent DoS attacks that artificially inflate the number of sigops, the protocol therefore imposes a limit on the number of sigops allowed per block, so that the validation workload remains manageable for nodes. This limit is 80,000 sigops per block at most. To count them, nodes follow these rules:

In the `scriptPubKey`, `OP_CHECKSIG` and `OP_CHECKSIGVERIFY` count as 4 sigops. `OP_CHECKMULTISIG` and `OP_CHECKMULTISIGVERIFY` count as 80 sigops. The reason is that, when counting, these operations are multiplied by 4 when they are not part of a SegWit input (for a P2WPKH, the number of sigops is therefore 1);

In the `redeemScript`, `OP_CHECKSIG` and `OP_CHECKSIGVERIFY` also count as 4 sigops, and `OP_CHECKMULTISIG` and `OP_CHECKMULTISIGVERIFY` count as `4n` if they are preceded by `OP_n`, or as 80 sigops otherwise;

For the `witnessScript`, `OP_CHECKSIG` and `OP_CHECKSIGVERIFY` count as 1 sigop, and `OP_CHECKMULTISIG` and `OP_CHECKMULTISIGVERIFY` count as `n` if they are preceded by `OP_n`, or as 20 sigops otherwise;

In Taproot scripts, sigops are handled differently from traditional scripts. Instead of directly counting each signature operation, Taproot introduces a sigops budget for each transaction input, proportional to the size of that input. This budget is 50 sigops plus the size in bytes of the input's witness. Each signature operation reduces the budget by 50. If executing a signature operation drops the budget below zero, the script is invalid. This method allows more flexibility in Taproot scripts, while keeping protection against potential sigops abuse by tying it directly to the weight of the input. As a result, Taproot scripts are not counted toward the limit of 80,000 sigops per block.
