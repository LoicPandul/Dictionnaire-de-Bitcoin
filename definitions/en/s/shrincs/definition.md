Contraction of *Shrunken SPHINCS*. Hash-based signature scheme designed for Bitcoin, which combines a very compact stateful signature with a stateless fallback based on the SLH-DSA algorithms. The signer uses the stateful path as long as it knows its state and has a leaf left, and switches to the stateless path as soon as the state is lost or the leaves are exhausted, for example after restoring a backup. A signature from either path is enough to pass verification.

It addresses a backup problem. A stateful scheme like XMSS signs shorter (2,500 bytes for XMSS-SHA2_10_256, versus 7,856 for SLH-DSA-SHA2-128s) but requires the signer to remember the leaves already used, and the mnemonic phrase of a wallet does not contain this state (see HASH-BASED SIGNATURE). A stateless scheme does not have this flaw, but its signatures are thousands of bytes long. SHRINCS takes both: if the state is correct, Alice signs with as little as 548 bytes (up to 4,619 depending on the leaf), otherwise she signs statelessly. The draft requires that an implementation that does not have a correct state, for example after a restore from a static backup, refuse the stateful path and use only the stateless path. The funds therefore remain spendable, but at a higher cost.

The public key is 48 bytes: a public seed `pk_seed`, the root `sl_root` of the stateless path, and the root `sf_root` of the stateful path, each 16 bytes. The stateless path is SLH-DSA (see SLH-DSA), using the FIPS 205 algorithms but a nonstandard parameter set ($n = 16$, 5 layers of trees of height 9, 10 FORS trees) that caps the number of signatures per key at $2^{40}$ to keep the targeted security level and reduces the signature from 7,856 bytes (SLH-DSA-SHA2-128s) to 5,777 bytes, flag byte included. The stateful path is a "flexible" XMSS tree (FXMSS) of WOTS+C one-time signatures (see WOTS - WINTERNITZ ONE-TIME SIGNATURE), which replace checksum chains with a constant sum, here 240, that the signer reaches by searching for a 2-byte search counter. The hash function is `SHA256`, whose outputs for tree hashes and pseudorandom functions are truncated to 16 bytes, to target NIST category 1.

To sign statefully, Alice reads her state counter, increments it in persistent storage, then takes the designated WOTS+C leaf and reveals its 32 chain values of 16 bytes (512 bytes) with the authentication path up to `sf_root`. A signature starts with a flag byte, which is 255 for a stateless signature and otherwise gives the height of the leaf used (from 0 to 254). Bob reads this byte and verifies the corresponding path: he climbs the path up to `sf_root`, or runs the SLH-DSA verification up to `sl_root`. Each path also binds the root of the other to the signed message. Reusing the same value of the state counter for two messages would allow an observer to forge signatures. Since each stateful signature reveals the leaf used, a wallet can at least refuse, before publishing, a leaf already seen under the same key.

The signer chooses the shape of the tree at key generation, and the verifier does not need to know it. The unbalanced shape, UXMSS, suits personal wallets: the first leaf is one level from the root, the second two, and so on up to 255. A signature is then 548 bytes for the first leaf (1 flag byte, 16 of randomness, 1 of index, and 530 of FXMSS signature) and 564 for the second, then about 16 bytes more with each signature, up to 4,619 bytes (the index also grows from 1 to 8 bytes with depth). Public key included, the smallest combination is 596 bytes, which is 13.23 times smaller than SLH-DSA-SHA2-128s (7,888 bytes), according to the specification. The balanced shape, BXMSS, gives constant-size signatures and is better suited to address reuse or layer 2 protocols.

The authors state the limits. Generating the key and signing are expensive: for a UXMSS of depth 255, 425,982 `SHA256` compressions for the key and 1,707,229 on average for a stateless signature. SHRINCS offers no algebraic structure, so neither BIP-0032-style public key derivation nor MuSig-style multisignature. The draft still lacks a security proof, and the Python reference implementation, which is slow and does not run in constant time, is not meant for production. The on-chain cost remains debated. On August 31, 2026, Antoine Riard estimated that a 5,777-byte stateless signature, 90 times larger than a Schnorr signature, would multiply the fee-bumping reserves of layer 2 protocols by as much, unless these fields get a discount. Conduition replied, on September 4, that a transaction with 2 inputs and 2 outputs weighs 840 weight units in P2TR with Schnorr, against 12,426 in P2MR with stateless SHRINCS, about 14.8 times more.

As of October 25, 2026, SHRINCS is a BIP draft without a number, which has not been submitted to the BIPs repository, and which specifies only the signature scheme. Deploying it would require other proposals and at least a new output type. A companion draft imagines a new tapscript leaf version (0xC2 in the draft) where `OP_CHECKSIG` would read an algorithm flag at the start of the public key, to choose between SHRINCS and BIP340 Schnorr, and would raise the size limit of a stack element from 520 to 6,000 bytes so that a SHRINCS signature fits. The announcement email carries the notice "Do NOT use in production".

The construction is sketched in appendix B.3 of the paper by Mikhail Kudinov and Jonas Nick, *Hash-based Signature Schemes for Bitcoin* (Blockstream Research, December 5, 2025), which proposes an unbalanced XMSS with a safe fallback in case of restoration. The name and the first form appeared on December 11, 2025, in a Delving Bitcoin thread opened by Jonas Nick, titled "SHRINCS: 324-byte stateful post-quantum signatures with static backups", where 324 bytes is the size of the first stateful signature in that version. The SHRINCS/shrincs-bip working repository was created on May 10, 2026. On August 26, 2026, Conduition announced on the bitcoindev mailing list a first BIP draft on behalf of the SHRINCS working group, which Optech picked up on September 4. This draft raises the first stateful signature to 548 bytes, in exchange for much faster parameters. The declared authors are Conduition, Ethan Heilman, Mikhail Kudinov, Oleksandr Kurbatov, Jonas Nick, and remix7531. Jonas Nick and remix7531 also published libshrincs, a prototype C library whose WOTS+C code, the one-time signature of the stateful path, is machine-verified.

*The 324-byte figure, quoted in the first messages, corresponds to the December 2025 construction; the 2026 BIP draft gives 548 bytes at minimum.*
