Bitcoin transaction that, in addition to following the consensus rules, also falls within the standardness rules configured by default on Bitcoin Core nodes. These standardness rules are enforced individually by each Bitcoin node, on top of the consensus rules, to define the structure of the unconfirmed transactions it accepts into its mempool and relays to its peers.

These rules are therefore configured and executed locally by each node and may vary from one node to another. They apply only to unconfirmed transactions. A node will therefore accept a transaction it would judge non-standard only if it is already included in a valid block.

Note that most nodes leave the default configuration as predefined in Bitcoin Core, which in effect makes the standardness rules homogeneous across the network. A transaction that complies with the consensus rules but not with these standardness rules will have difficulty propagating across the network. It can nonetheless be included in a valid block if it ever reaches a miner. In practice, these transactions, called non-standard, are often sent directly to a miner through channels outside Bitcoin's peer-to-peer network. This is often the only way to confirm this type of transaction. For example, a transaction that allocates no fees is both valid under the consensus rules and non-standard, because Bitcoin Core's default policy for the `minRelayTxFee` parameter is `0.000001` (in BTC/kvB).
