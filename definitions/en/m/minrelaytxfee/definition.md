Bitcoin Core policy setting (option `-minrelaytxfee`) that sets the fee rate below which a node rejects an unconfirmed transaction considered on its own (a package is judged on its overall rate): the node does not accept it into its mempool and therefore does not relay it to its peers. It is a policy rule, specific to each node, and not a consensus rule: a block containing a transaction below this rate remains valid.

The code expresses default values in satoshis per virtual kilobyte (sat/kvB), while the option is entered in BTC/kvB (`-minrelaytxfee=0.00000100` for 100 sat/kvB), and the rate is more commonly read in sat/vB. Take Alice, who broadcasts a 200 vB transaction. With a threshold of 1 sat/vB, her fees must reach at least 200 satoshis; with a threshold of 0.1 sat/vB, 20 satoshis are enough. If she pays less, the node rejects the transaction with the reason "min relay fee not met" (an error returned by `sendrawtransaction`) and does not forward it. This floor combines with the mempool's dynamic minimum rate: when the mempool reaches its size limit and evicts transactions, the required minimum rises above the fixed threshold, and the node keeps the higher of the two. The `getmempoolinfo` RPC returns this maximum under the name `mempoolminfee`, next to `minrelaytxfee`.

The threshold also acts between peers. With the `feefilter` message (BIP-0133, Bitcoin Core 0.13.0), a node tells its peers the rate below which it no longer wants transaction announcements, and since Bitcoin Core 0.15, this rate never drops below `minrelaytxfee`. Since Bitcoin Core 31.0, a package of transactions is checked on its overall rate: a well-paying child can get a parent below the threshold accepted (see PACKAGE RELAY).

Three neighboring settings remain distinct. `-incrementalrelayfee` sets the additional fees a replacement must pay, at this rate multiplied by its size (see RBF - REPLACE-BY-FEE), and the margin added to the rate of evicted transactions to raise the dynamic minimum; Bitcoin Core gives both options the same default, raises `minrelaytxfee` if `-incrementalrelayfee` is set higher without it being specified, and the release notes advise changing them together. The dust threshold depends on another setting (see DUSTRELAYFEE). The Bitcoin Core wallet has its own, `-mintxfee`, which has stayed at 1 sat/vB: by default, the wallet does not create a transaction below the higher of this rate and `minrelaytxfee`, unless a rate is imposed with `fundrawtransaction` or `walletcreatefundedpsbt`. For the size of relayed data, see DATACARRIERSIZE.

The choice of threshold is debated. On Delving Bitcoin, on July 31, 2025, Gloria Zhao describes the minimum relay rate as a protection rule against denial of service, "a price per unit of bandwidth": a relayed transaction is downloaded by tens of thousands of nodes. She picks up a calculation by Anthony Towns: with 100,000 nodes and bandwidth at 10 cents per gigabyte, the relay cost was about 0.01 sat/vB at 2025 prices, and 0.1 sat/vB would cover a network of 1 million nodes. Bitcoin Optech (Newsletter #368, August 22, 2025) cites as reasons the rising number of blocks mined with transactions below 1 sat/vB, the rising number of pools mining them, and the rising price of bitcoin; Zhao adds that blocks rich in such transactions propagate more slowly to nodes that had rejected them or had not heard of them earlier. In 2022, Optech (Newsletter #212) relayed, in a summary of a discussion, the idea that the previous attempt to lower the rate had been held back because a lower rate also reduced the cost of several minor denial-of-service attacks. In Zhao's thread, garlonicon asks whether standardness rules should be dropped as soon as miners confirm non-standard transactions: by that logic, he observes, any existing limit could be lifted.

The default was 1 sat/vB up to Bitcoin Core 29.0 (28.2 on the 28.x branch), apart from a stint at 5 sat/vB in a few 2015 releases; version 0.8.2 set it at 10,000 sat/kB. It has been 0.1 sat/vB (100 sat/kvB) since PR #33106, merged on August 15, 2025 and released in Bitcoin Core 29.1 (September 4, 2025), 30.0 (October 10, 2025), and 28.3 (October 17, 2025). The same PR lowers `-blockmintxfee`, the miners' threshold for building a block, to 0.001 sat/vB. The 30.0 release notes specify that, until these defaults are widely adopted, a transaction below the old threshold is not guaranteed to propagate or to be confirmed.

*`minrelaytxfee` should not be confused with the rate the wallet chooses for a transaction it creates. The setting applies to unconfirmed transactions that the node accepts into its mempool (received from its peers, submitted by RPC, or reloaded), whereas the wallet has its own floor, `-mintxfee`, and never goes below `minrelaytxfee`.*
