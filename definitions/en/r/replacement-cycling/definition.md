Attack that exploits transaction replacement rules (RBF) to remove an unconfirmed transaction from full nodes' mempools, without any alternative transaction taking its place. It mainly affects multi-party protocols that depend on CPFP to bump fees, such as the Lightning Network. This vulnerability was publicly disclosed in October 2023 by Antoine Riard (CVE-2023-40231 to CVE-2023-40234).

The attack unfolds in several cyclical steps. Bob broadcasts his unilateral exit transaction together with a child transaction for fee bumping via CPFP. Mallory responds by broadcasting her own competing exit transaction, which conflicts with Bob's since they spend the same inputs, together with a child transaction paying higher fees. Bob's transaction is replaced in the mempools. Mallory then replaces her own child transaction with a transaction unrelated to the channel, which causes her exit transaction to be evicted. The mempool now contains no settlement transaction at all. Bob can rebroadcast, but Mallory repeats the cycle on every attempt, each iteration costing her a new UTXO or a higher fee rate.

This attack is particularly dangerous for Lightning Network HTLCs, which must be resolved within a defined time window. If the attacker keeps the victim from confirming its transaction before the deadline expires, the attacker can claim the funds. Lightning Network implementations have deployed several mitigations: aggressive and frequent rebroadcasting of transactions, monitoring the local mempool to detect preimages before they are evicted, and raising the CLTV expiry deltas (`cltv_expiry_delta`).
