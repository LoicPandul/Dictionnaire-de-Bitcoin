Network protocol proposal that aims to improve the efficiency of relaying unconfirmed transactions between Bitcoin nodes.

In classic relay, each transaction is propagated through a system in which each node forwards every transaction it learns about to all of its peers. The problem is that this causes a lot of redundancy and spends bandwidth on duplicates. Many transaction announcements turn out to be useless, because the recipient already knows about those transactions, and each node needs to learn of each transaction only once. Erlay proposes limiting by default to 8 the number of peers to which a node directly sends the transactions it learns about, then using a reconciliation process based on the minisketch library to share the missing transactions more efficiently.

Erlay would reduce bandwidth consumption by about 40%, which would make running a full node more accessible to users with limited Internet connections and would thus favor better decentralization of the network. The protocol would also keep bandwidth consumption nearly constant as the number of connections increases. This means it would be much easier for node operators to accept a very large number of connections from their peers, which would strengthen the security of the Bitcoin network by reducing the risks of partitioning, intentional or accidental. In addition, Erlay would make it harder to determine the originating node of a transaction, which would increase privacy for users of nodes that do not operate over Tor.

Erlay is proposed in BIP-0330, which has Draft status. Bitcoin Core 32.0 contains partial support for reconciliation, disabled by default and enabled only through the debug option `-txreconciliation`.
