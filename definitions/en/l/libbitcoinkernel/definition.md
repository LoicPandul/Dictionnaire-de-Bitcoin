Bitcoin Core library that isolates the validation engine (consensus rules, chainstate, block storage) from the rest of the software, so that other programs can use it. A project that wants to validate blocks or scripts exactly as Bitcoin Core does no longer has to copy its code or run a full node: it links the library. In the intended organization of Bitcoin Core's code, the library should depend only on the consensus, cryptography, and utility libraries, and the node module (networking, RPC) is meant to build on it, even though the node today compiles those same files directly instead of linking the library.

The library is defined in the `src/kernel/` directory (the code it compiles comes mostly from other directories of `src/`). The `bitcoinkernel.h` file is its C language interface: a program creates a context in it (which carries the chain parameters and the callbacks for notification of events), then a chainstate manager that loads the chain state from a data directory. Let's take an example. Alice writes a block indexer. Her program feeds it the blocks it receives one by one; the library validates them with Bitcoin Core's rules and notifies her of the acceptance or rejection of each one, with the reason. Alice can also walk the block index, read back a block and its undo data from disk, or separately verify that a transaction input satisfies the script of the output it spends (`btck_script_pubkey_verify`). Since July 2026, the interface also exposes the witness stack and the `scriptSig` of a transaction's inputs (Bitcoin Core #35380), which is useful, for example, to Silent Payments scanners, which need the public keys of the inputs.

The choice of a C interface comes from its advantages: a shared library shipped with a C++ header suffers from name mangling and an unstable ABI, whereas C offers a reasonably stable ABI and integration tooling for almost every language. Bindings exist for Rust, Python, Go, and Java. Hardware-optimized SHA256 is also available, thanks to a built-in static context that detects and self-checks the SHA256 implementation, and which comes with a self-test of the secp256k1 static context.

This interface remains experimental. Its header is not versioned and not stable: the file warns that breaking changes should be expected. Building the library goes through a CMake option, `BUILD_KERNEL_LIB`, which the code's documentation describes as experimental. When it was merged, it was limited to block operations and script verification.

The idea goes back to a project launched in 2022, whose first building blocks were a library extracted from Bitcoin Core's code by Carl Dong (merged on April 28, 2022, Bitcoin Core #24322) and a demonstration executable, `bitcoin-chainstate`. A tracking issue, opened on May 6, 2023 by sedited, gathers the work. In the release notes of version 27.0, the team deprecates libbitcoinconsensus, a library that saw little adoption, and announces that libbitcoinkernel will eventually offer a more useful interface, aware of the entire UTXO set. libbitcoinconsensus is removed in version 28.0. On November 4, 2025, Bitcoin Core merges the C interface by sedited, alias TheCharlatan (#30595), with at least the same coverage as libbitcoinconsensus. Bitcoin Optech reports on it in its November 2025 newsletter and in its year-in-review of December 19, 2025.

*Not to be confused with libbitcoinconsensus, the older library that only verified scripts. Here, the name "kernel" refers to the validation engine, not to the kernel of an operating system.*
