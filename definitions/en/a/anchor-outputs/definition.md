Mechanism, built into the BOLTs as `option_anchors` (BOLT-03), that improves transaction fee management in Lightning channels. At each state change in a Lightning channel, the parties create and sign a new commitment transaction that reflects the new distribution of funds within the channel. The problem with this mechanism lies in determining the transaction fees at the time the transaction is created. Transaction fees on the Bitcoin network fluctuate sharply, both upward and downward. If the fees set for the latest commitment transaction are insufficient when the channel is force-closed, not only will the transaction take a considerable time to confirm, but timelock mechanisms could also allow a theft of funds. With anchor outputs, each commitment transaction contains two small additional outputs of 330 sats, one for each party, which at first only the party concerned can spend (each is locked to its funding key; anyone can sweep an unused anchor 16 blocks after confirmation). In case of network congestion and rising fees, the party closing the channel spends its anchor output in a high-fee child transaction: this is a Child Pays For Parent (CPFP), which gets the commitment transaction confirmed after the fact, thereby ensuring that the Lightning channel closes quickly enough. The 330 sats of each anchor are taken from the balance of the channel funder.
